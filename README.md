# FinRAG-Agent：金融长文档问答 Agent

基于 BM25 符号检索与 LLM 工具调用循环的金融文档问答系统，处理五类金融长文档（合同 / 财报 / 保险条款 / 监管法规 / 行业研报）中的选择题问答。

项目源自 AFAC2025 金融挑战赛，核心叙事：**在不依赖 Embedding 的符号检索主路径上，通过分层混合召回与 Agent 化的证据收集，显著优于朴素向量 RAG**。

## 核心特性

- **符号检索主路径**：BM25（jieba 分词）+ 数值归一化精确匹配 + 短语/实体加分 + 表格保底，无需 Embedding 即可实现高召回
- **向量兜底混合召回**：Chroma 嵌入式向量库（qwen3.7-text-embedding-flash），语义最近邻补位符号检索漏召回的场景
- **Agent 化问答**：Qwen function calling 多轮工具循环（search_number / search_phrase / search_entity / search_keyword），首轮强制搜索、按题型分级轮数预算
- **引用与拒答机制**：证据统一编号 [证据N]，模型引用经校验（检测幻觉引用），数值结论强制证据支撑，拒答信号可统计
- **预算控制**：每题 token 熔断、工具连续空结果降级、API 带重试
- **分层评测集**：自动构建五层题目（单跳事实 / 表格数值 / 跨文档 / 时效版本 / 无答案陷阱），金标锚定 chunk 级，支持四基线对比

## 系统架构

```
PDF/预解析 JSON
    ↓
文档解析 → 分块（条款边界感知，表格独立 chunk）→ 实体提取 → 异构图构建
    ↓
领域索引（BM25 + 数值索引 + 短语索引 + 实体索引 + 倒排索引）   Chroma 向量库（兜底）
    ↓                      ↓                                        ↓
问题 + 选项 → 查询扩展（别名/同义词/股票代码） → 符号检索 → 向量兜底补位
    ↓
Qwen 工具调用循环（多轮证据收集，预算熔断）
    ↓
引用校验 + 拒答检测 + 答案提取 → answer_source 溯源标记
```

## 评测结果

同一问答模型（qwen3.8-flash，Responses API）下四基线对比（50 题分层评测集，金标锚定 chunk 级）：

| 基线 | 总体准确率 | token/题 | 陷阱题拒答率 | 说明 |
|------|-----------|---------|--------------|------|
| 1. LLM 裸问 | 34.0% | 547 | 0% | 无证据，表格数值/跨文档/拒答全崩 |
| 2. 朴素向量 RAG | 66.0% | 1,873 | 38.5% | Chroma 语义 top-8（行业默认方案） |
| 3. 符号检索单轮 | **72.0%** | 1,908 | 38.5% | BM25+数值/短语/实体加分，**优于朴素向量** |
| 4. 完整系统（本方案） | **84.0%** | 10,853 | 53.8% | 符号检索 + 多轮工具循环 + 引用/拒答校验 |

关键结论：
- **符号检索 72.0% > 朴素向量 RAG 66.0%**：条款术语（合同 76.9% vs 53.8%）与单跳事实（91.7% vs 83.3%）上，BM25+领域加分显著优于纯语义匹配
- **完整系统 84.0%**：相对符号单轮 +12 分（表格数值 78.3%→95.7%，单跳 91.7%→100%），相对裸问 +50 分，代价是 5.7 倍 token（预算熔断控制单题上限）
- 拒答机制：裸问对 13 道无答案陷阱题 0% 拒答（全错），完整系统拒答 7/13 且误拒仅 2 题

检索层直接对照（229 题，Recall@10 / MRR@10，金标锚定 chunk 级）：**符号检索 74.2% / 0.571** vs 向量检索 52.0% / 0.337——跨文档题差距最大（100% vs 18.2%），时效版本题（75.0% vs 12.5%）、表格数值题（93.3% vs 77.3%）符号检索全面领先，详见 `eval/report_retrieval_v1.md`。

**229 题全量实测**（`eval/report_full_system_trapfix_full.md`，含零锚点强制拒答）：总体 **92.1%**，token/题 10,590；分层 single_hop 95.6%、multi_hop 100%、table_numeric 90.7%、unanswerable 88.9%、temporal 75.0%；无答案陷阱拒答率 **88.9%** 且**误拒 0 题**。

### 金融场景核心指标：强追溯 + 可信

金融问答的硬需求不是"答得多"，而是**每条结论可审计、无证据不开口**。对应三项核心指标：

**强追溯（可审计性）** —— 20 题实测（`eval/report_full_system_cit.md`）：
| 指标 | 数值 | 说明 |
|------|------|------|
| 引用有效率 | **100%**（39/39） | 模型引用的证据编号全部指向证据池真实条目，**零幻觉引用** |
| 证据覆盖率 | 17.6% | 引用是精选而非堆砌——答案只锚定支撑它的证据子集 |
| 溯源链路 | 答案 → [证据N] → chunk_id → 文档/页码 | 每条答案可回溯到原文段落，满足审计要求 |

**可信度（拒答与幻觉控制）** —— 50 题实测：
| 指标 | 数值 | 对照 |
|------|------|------|
| 无答案陷阱拒答率 | **53.8%**（7/13） | 裸问基线 0%（13 题全硬答全错） |
| 误拒率 | 2 题 | 有金标答案却被拒答的惩罚项 |
| 数值结论证据校验 | strict 模式 | 数值答案无证据支撑时触发重写，而非直接输出 |

**成本确定性（预算控制）**：单题 token 熔断（multi 5 轮 / mcq 3 轮 / tf 2 轮分级预算）、工具连续空结果降级、API 带重试——金融生产环境的成本上限可控。

## 评测指标体系

| 指标 | 说明 |
|------|------|
| 分层准确率 | 五层题型分别统计（单跳 30% / 表格数值 25% / 跨文档 20% / 时效版本 10% / 无答案陷阱 15%） |
| Recall@10 / MRR@10 | 金标锚定 chunk 级，纯检索评测无需调用 LLM |
| 拒答率 / 误拒率 | 无答案陷阱题的拒答正确性；有答案题的误拒惩罚 |
| Token 效率 | 平均 token/题，预算熔断保障 |

四种基线对比（`eval/run_eval.py`）：LLM 裸问 / 朴素向量 RAG / 符号检索单轮 / 完整系统（Agent 工具循环）。

## 快速开始

```bash
# 1. 安装依赖（建议 Python 3.10+）
pip install -r requirements.txt

# 2. 配置密钥
copy .env.example .env   # 编辑 .env 填入 API Key

# 3. 放置文档数据（JSON 格式，见 data/ 目录结构说明）
#    financial_contracts / financial_reports / insurance / regulatory / research

# 4. 构建索引（首次运行自动构建并缓存到 cache/）
python run_100.py

# 5. 构建向量库（可选，用于向量兜底）
python vector_store.py --build

# 6. 运行评测
python eval/run_eval.py --mode retrieval          # 纯检索评测（Recall@10 / MRR@10）
python eval/run_eval.py --mode full_system        # 完整系统评测
python eval/build_eval_set.py --max 300           # 自动构建评测集

# 7. 启动检索服务
uvicorn serve.api:app --host 0.0.0.0 --port 8000
```

### 测试数据构造方式

评测集 [eval_set_v2_100.jsonl](eval/eval_set_v2_100.jsonl) 由 [question_gen_v2.py](eval/question_gen_v2.py) 从索引 chunk 自动构造（seed 固定，可复现），共 100 题：单选 40（含 6 道无答案陷阱）+ 多选 20 + 逻辑推理 20 + 数值计算 20，覆盖合同/财报/保险/监管/研报五领域。

- **多选**：同文档抽取 3 条真实表述 + 2 条篡改表述（数值 ×2），金标=真实表述选项
- **逻辑推理**：条款规则的方向/阈值篡改题 + 同表数值比较题
- **数值计算**：同表同量纲指标的和/差运算，选项含原始单值干扰项（金标不在原文，检验真实运算）
- **陷阱题**：抽取文档未提及的指标反向命题，检验拒答能力

每题携带 `gold_doc_ids` / `gold_chunk_ids` / `source_anchor` 三级出处，构建时质检：金标锚点必须命中金标 chunk、篡改值必须不在全文出现（反向验证）。
